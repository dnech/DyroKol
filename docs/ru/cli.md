# Командная строка и конфигурация

```
dyrokol server [флаги]               запустить relay
dyrokol client [флаги]               запустить агента
dyrokol service <install|uninstall|start|stop|restart|status>   служба Windows
dyrokol help
```

Роль всегда указывается явно: запуск без аргументов печатает справку и завершается с кодом 2.
Подробную справку по флагам даёт `dyrokol <команда> --help`.

Обе роли завершаются корректно по `SIGINT`/`SIGTERM` (Ctrl+C): relay дописывает статистику и
запечатывает базу на диск, агент закрывает порты.

## Порядок приоритета настроек

Для каждого параметра берётся первое найденное значение:

1. **флаг** командной строки;
2. **переменная окружения** `DYROKOL_<ИМЯ>`;
3. значение из **файла конфигурации** (для relay);
4. **значение по умолчанию**.

Пустая переменная окружения считается незаданной.

## Каталог данных

Все файлы по умолчанию лежат в **`~/.config/dyrokol`** (или `$XDG_CONFIG_HOME/dyrokol`, если задан).
Каталог меняется флагом `--dir` / `DYROKOL_DIR`. Если указан `--config`, а `--dir` нет, каталогом
данных становится каталог файла конфигурации. Относительные пути (`db`, `cert`, `key`) считаются от
каталога данных; абсолютные используются как есть.

| Файл | Кто создаёт | Что внутри |
| --- | --- | --- |
| `dyrokol-server.yaml` | relay | конфигурация relay (создаётся при первом запуске) |
| `dyrokol.crt`, `dyrokol.key` | relay | самоподписанный TLS-сертификат (ECDSA P-256, срок 5 лет) и ключ (`0600`) |
| `dyrokol.db.enc` | relay | зашифрованная конфигурация: машины, порты, маршруты, настройки |
| `dyrokol.data.db.enc` | relay | зашифрованная статистика: счётчики, график, адреса, журнал. Можно удалить при остановленном relay, он создаст пустую |
| `dyrokol.yaml` | агент | конфигурация агента: список relay и токены (`0600`) |
| `pins.json` | агент | запомненные отпечатки сертификатов relay (рядом с конфигом агента) |

Имя второго файла базы выводится из первого: `имя.db.enc` → `имя.data.db.enc`.
Во время записи рядом появляется временный `*.tmp`; он заменяет основной файл атомарным
переименованием, поэтому обрыв питания не оставляет полузаписанную базу.

## Relay: `dyrokol server`

```
dyrokol server [флаги]
```

| Флаг | Переменная | По умолчанию | Описание |
| --- | --- | --- | --- |
| `-d`, `--dir DIR` | `DYROKOL_DIR` | `~/.config/dyrokol` | каталог данных |
| `-c`, `--config PATH` | `DYROKOL_CONFIG` | `<dir>/dyrokol-server.yaml` | файл конфигурации; создаётся, если его нет |
| `-l`, `--listen ADDR` | `DYROKOL_LISTEN` | `:4443` | адрес туннельного порта (TLS), его используют агенты |
| `-a`, `--admin ADDR` | `DYROKOL_ADMIN` | нет | необязательный локальный TCP-вход в админку, например `127.0.0.1:9180`. По умолчанию админ-порт не открывается: админка доступна только через админ-машину |
| `-b`, `--db PATH` | `DYROKOL_DB` | `<dir>/dyrokol.db.enc` | зашифрованная база |
| `-e`, `--cert PATH` | `DYROKOL_CERT` | `<dir>/dyrokol.crt` | TLS-сертификат |
| `-k`, `--key PATH` | `DYROKOL_KEY` | `<dir>/dyrokol.key` | TLS-ключ |
| `-t`, `--token TOKEN` | `DYROKOL_ADMIN_TOKEN` | генерируется | токен админ-API |
| `-f`, `--token-file PATH` | `DYROKOL_ADMIN_TOKEN_FILE` | — | прочитать токен админ-API из файла (пробелы по краям отбрасываются) |
| `-x`, `--token-sha256 HEX` | `DYROKOL_ADMIN_TOKEN_SHA256` | — | хранить только SHA-256 токена, а не сам токен |

### Токен админ-API

Токен защищает админ-API и веб-интерфейс (заголовок `X-Dyrokol-Api`). Варианты:

- **Не задавать**: при первом запуске токен генерируется и хранится **внутри зашифрованной базы** (не в
  конфиге и не в логе); после перезапусков он прежний. Админ-машина получает его при подключении и печатает
  как `admin ui token`.
- **`--token` / `--token-file`**: постоянный токен. Передача файлом надёжнее, чем флагом
  (флаги видны в списке процессов).
- **`--token-sha256`**: relay знает только хэш токена. Приемлемо, если токен вы храните сами; но
  тогда relay **не может передать токен админ-машинам**, и они напишут «admin ui token: unknown»:
  вводить его придётся вручную. Хэш получают так: `printf %s 'мой-токен' | sha256sum`.

Приоритет, если заданы несколько: `--token-file` > `--token`, а `--token-sha256` имеет приоритет
над обоими для проверки (plain-токен тогда не рассылается).

### Файл конфигурации relay

Создаётся при первом запуске со значениями по умолчанию; флаги и переменные окружения его
**не** изменяют, а лишь переопределяют на время запуска.

```yaml
listen: :4443                 # туннельный порт для агентов
# admin: 127.0.0.1:9180       # необязательный локальный вход в админку (по умолчанию выкл.; только loopback)
db: dyrokol.db.enc            # относительные пути считаются от каталога данных
cert: dyrokol.crt
key: dyrokol.key
# admin_token: ""             # необязательный фиксированный токен админ-API (иначе создаётся один раз и хранится в базе)
# admin_token_sha256: ""
```

### Что происходит при запуске

1. Загружается или создаётся TLS-сертификат (если есть только одна половина пары — ошибка).
2. Открывается туннельный порт. **База остаётся заблокированной.**
3. Админ-интерфейс, relay-порты и фоновые задачи стартуют, когда первая машина разблокирует базу
   (или инициализирует её) — см. [Архитектуру](architecture.md#жизненный-цикл-relay).

## Агент: `dyrokol client`

```
dyrokol client [флаги]
```

| Флаг | Переменная | По умолчанию | Описание |
| --- | --- | --- | --- |
| `-d`, `--dir DIR` | `DYROKOL_DIR` | `~/.config/dyrokol` | каталог данных |
| `-c`, `--config PATH` | `DYROKOL_CONFIG` | `<dir>/dyrokol.yaml` | конфигурация агента |
| `-s`, `--server ADDR` | `DYROKOL_SERVER` | — | адрес relay: домен или IP, порт необязателен (по умолчанию `4443`), например `vps.example.com` или `203.0.113.5:4443`; префикс `https://` игнорируется |
| `-t`, `--token TOKEN` | `DYROKOL_TOKEN` | — | токен **туннеля** этой машины (не токен админки) |
| `-p`, `--db-password PASS` | `DYROKOL_DB_PASSWORD` | — | пароль базы для автоматической разблокировки relay; нужен только машине, которая должна разблокировать relay после перезапуска (обычно админ-машине) |
| `-a`, `--admin-listen ADDR` | `DYROKOL_ADMIN_LISTEN` | `127.0.0.1:9181` | локальный адрес админки (только для роли admin). Просто порт (`9182`) означает `127.0.0.1:9182` |
| `--no-admin` | `DYROKOL_NO_ADMIN` | выкл. | не открывать локальную админку |
| `-i`, `--tls-pin PIN` | `DYROKOL_TLS_PIN` | — | ожидаемый отпечаток сертификата relay (`sha256:…`) |
| `-n`, `--pins PATH` | `DYROKOL_PINS` | рядом с конфигом | файл запомненных отпечатков |

### Три режима запуска

| Команда | Что делает |
| --- | --- |
| `dyrokol client` | Запускает агента по конфигу. Нет конфига — понятная ошибка. |
| `dyrokol client -s host:port` | **Регистрация первой машины.** Инициализирует базу на relay (машина становится admin), сохраняет токен и пароль в конфиг и запускает агента. Работает только на relay без базы: иначе ответ `db_exists`. |
| `dyrokol client --init` | Создаёт файл конфигурации с **заглушками** (адрес relay, токен), если его нет, и выходит. То же происходит, когда `dyrokol client` не находит конфиг: файл создаётся, а агент просит его заполнить. |
| `dyrokol client -s host:port -t TOKEN [-p PASS]` | Запускает агента для одного relay **без** чтения и записи конфига. |

Другие машины создаются в админке (**Machines → Add machine**) и запускаются третьей формой либо
записываются в конфиг агента вручную.

### Файл конфигурации агента

```yaml
servers:
  - addr: vps.example.com:4443       # адрес relay
    token: cl_…                      # токен туннеля этой машины
    db_password: …                   # пароль базы (необязательно, см. «Безопасность»)
    tls_pin: sha256:…                # необязательно: явный отпечаток вместо TOFU
    admin_listen: 127.0.0.1:9181     # необязательно: где открыть админку (роль admin); можно просто `9182`.
                                     # По умолчанию: 9181 для первого relay, 9182 для второго и т.д.
    disable_admin: false             # необязательно: не открывать админку
  - addr: second-relay.example.org:4443   # можно несколько relay
    token: cl_…
```

Для каждого relay агент поддерживает отдельную сессию и переподключается сам. Пауза между
попытками растёт с 1 до 15 секунд и сбрасывается, если соединение прожило дольше 30 секунд.

Файл записывается с правами `0600`: в нём лежат секреты.

### Проверка отпечатка сертификата

- По умолчанию (**TOFU**): первое подключение запоминает отпечаток в `pins.json`; любое отличие
  потом — ошибка `certificate pin mismatch`.
- `tls_pin` / `--tls-pin` задаёт отпечаток явно, и он имеет приоритет над `pins.json`.
- Если вы сознательно пересоздали сертификат relay, удалите запись о нём в `pins.json`.

### Локальная админка

Админ-машина слушает `admin_listen` на **loopback**, каждое соединение пересылается через туннель
на админ-порт relay. Если выбранный порт занят, агент берёт свободный loopback-порт и пишет его
в лог. Токен админки печатается в лог при каждом подключении
(`admin ui token: …`).

## Служба Windows: `dyrokol service`

```
dyrokol service install [--name ИМЯ] [--manual] [--no-start] <server|client> [флаги роли]
dyrokol service uninstall [--name ИМЯ]
dyrokol service start|stop|restart|status [--name ИМЯ]
```

Регистрирует `dyrokol.exe` как службу Windows, запускающую выбранную роль с указанными флагами.
Команды требуют прав администратора. Если у роли нет `--dir`/`--config`, добавляется
`--dir %ProgramData%\DyroKol`. Подробности, примеры и порядок регистрации агента —
в [Развёртывании](deployment.md#служба-windows).

`status` печатает состояние (`running`, `stopped`, …). На Linux и в Termux эти команды сообщают,
что не поддерживаются на этой платформе (код возврата 1): используйте systemd и другие
способы из [Развёртывания](deployment.md#как-сделать-из-dyrokol-демон-службу).

## Коды возврата

| Код | Когда |
| --- | --- |
| `0` | нормальное завершение, показ справки |
| `1` | ошибка запуска (конфиг, порт, сертификат, регистрация) |
| `2` | неверная команда или флаги |
