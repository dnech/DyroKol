# Диагностика

Где смотреть: **лог relay** (stdout или `journalctl -u dyrokol-server`), **лог агента** и страница
**Logs** в админке (события relay за 7 дней).

## Агент не подключается

В логе агента строка вида `[адрес] session: …`:

| Сообщение | Причина и решение |
| --- | --- |
| `dial: … connection refused` / `i/o timeout` | Relay недоступен: не запущен, закрыт порт в фаерволе, неверный адрес/порт. Проверьте `nc -vz vps.example.com 7443`. |
| `dial: transport: certificate pin mismatch for … got … want …` | Сертификат relay изменился (пересоздан или вы подключились к другому серверу). Если смена **ожидаема** — удалите запись об адресе в `pins.json` (или поправьте `tls_pin`). Если нет — это может быть подмена: проверьте отпечаток в логе relay. |
| `server error (locked): database is locked` | Relay перезапущен, а подключившийся агент не прислал пароль базы. Подключите агента с `db_password` (обычно админ-машину); остальные подтянутся после разблокировки. |
| `server error (locked): no database; register a machine first …` | На relay ещё нет базы. Зарегистрируйте первую машину: `dyrokol client --server host:7443`. |
| `server error (unauthorized): bad database password` | Пароль базы в конфиге агента неверный (например, после [переноса relay](deployment.md#перенос-relay-на-другой-сервер)). |
| `server error (unauthorized): unknown token` | Машина удалена или её токен перевыпущен. Возьмите актуальный токен (**Machines → Regenerate token**). |
| `client: …dyrokol.yaml: server #1 still has the placeholder values` | Конфиг агента создан с заглушками (`dyrokol client --init`, установщик, `service install client`). Впишите адрес relay и токен этой машины (**Machines → Add machine**). |
| `server error (version): protocol version … not supported` | Версии агента и relay несовместимы. Обновите оба. |
| `server error (db_exists): database already initialized` (при `client -s host:port`) | Регистрация без токена работает только на relay без базы. Если эта машина уже зарегистрирована, запустите `client -s host:port` с тем же `--dir`/`--config`: сохранённые настройки подхватятся. Создайте машину в админке и запустите агента с её токеном. |
| `connection closed by peer` по кругу | Сессию рвёт relay: роль/токен машины изменены, восстановлен бэкап — разовое явление. **Постоянно** — вероятно, **два агента используют один токен**: новая сессия вытесняет предыдущую, и они бесконечно выбивают друг друга. У каждой машины должен быть свой токен. |

## Админка

| Симптом | Решение |
| --- | --- |
| Админка не открывается | У relay нет админ-порта: админка доступна только на админ-машине (по умолчанию `http://127.0.0.1:9181`) и только после разблокировки базы, поэтому сначала подключите админ-машину. |
| `admin ui: cannot listen on …` в Logs | Необязательный адрес `--admin` занят на хосте relay. Задайте другой или уберите `--admin`. Туннели при этом работают. |
| Админ-машина пишет `admin ui: cannot listen on …` | Порт админки занят. Освободите его или задайте другой в `admin_listen` конфига клиента (`--admin-listen`); случайный порт не выбирается. Адрес и токен админки пишутся в лог при каждом (пере)подключении. |
| «This token is not valid for this relay» | Это не токен админ-API. Нужен `admin ui token` админ-машины (в её логе), а не токен туннеля (`adm_…`/`cl_…`). |
| `admin ui token: unknown` | Relay запущен с `--token-sha256` и не знает самого токена. Введите его вручную или перезапустите relay с `--token`/`--token-file`. |
| Токен менялся после перезапуска | Сгенерированный токен лежит в зашифрованной базе relay. Он меняется, только если базу создали заново или теперь передаётся `--token`. Ищите в логе relay ошибки `admin api token:`. |
| `403 cross-origin request rejected` | Запрос пришёл с другим `Origin`, чем адрес админки: обычно из-за прокси, который подменяет `Host`. Заходите напрямую или сохраняйте `Host`. |
| «Relay unreachable · retry» | Интерфейс не достучался до админки: нет туннеля админ-машины или relay остановлен. |

## Порты и проброс

| Симптом | Решение |
| --- | --- |
| При создании порта на relay: `cannot bind port: …` (409) | Порт занят на хосте relay или нет прав (порты ниже 1024: запускайте с `CAP_NET_BIND_SERVICE` или от root). Порт откатывается. |
| Статус порта на агенте: `bind failed` | Порт занят на хосте агента. Сообщение — под статусом (`cannot bind port 8080: address already in use`). Освободите порт: relay повторяет попытку каждые 15 секунд. |
| `port N is already bound by ingress M of …` | Тот же номер уже открыт другим relay-подключением этого же агента (один хост — один порт). |
| Статус `not routed` | Подключите порт к выходной точке на странице **Routes**. Нерутированный порт на relay закрывает соединения, на агенте — не открывается. |
| Статус `target offline` | Машина, исполняющая выходную точку, не в сети. Смотрите в **Machines**. |
| Соединение открывается и сразу закрывается | Смотрите логи: `egress: destination … denied by filter` (фильтр назначения), `… blocked by source filter` (фильтр источника), `dial … connection refused` (сервис не слушает на указанном хосте/порту **с точки зрения исполняющей машины**), `machine … is offline`. |
| Выходная точка `127.0.0.1:5000` «не работает» | `127.0.0.1` — адрес исполняющей машины, а не relay. Выберите в *Exits on* ту машину, где сервис. |
| Создание точки: `host must be a plain hostname or ip without port` | В поле *Target host* укажите только имя/адрес, без порта и слэшей. IPv6-адрес как литерал не принимается; используйте имя, которое резолвится в IPv6. |
| Ошибка `source filters cannot match ports` | Фильтр источника не может содержать порт (порт посетителя случайный). Уберите `:порт`; запись с портом допустима только в фильтре назначения. |

## Служба Windows

| Симптом | Решение |
| --- | --- |
| `access denied: run from an elevated (Administrator) prompt` | Откройте PowerShell «От имени администратора». |
| `service "DyroKol" already exists` | Удалите её (`dyrokol service uninstall`) или задайте другое `--name`. |
| Служба запускается и сразу останавливается | Прочитайте `dyrokol-service.log` в каталоге данных (по умолчанию `C:\ProgramData\DyroKol`). Обычно: агент ещё не зарегистрирован (нет `dyrokol.yaml`) или порт занят. |
| Из консоли агент работает, а как служба нет | Служба работает от `LocalSystem`, её конфиг лежит в `C:\ProgramData\DyroKol`, а не в вашем `%USERPROFILE%`. Регистрируйтесь с тем же `--dir`. |

## Данные и конфигурация

| Симптом | Решение |
| --- | --- |
| Графики и «Seen addresses» пусты | Данные появляются через 5–10 секунд после первого трафика, график строится по минутам. Если вы удалили `dyrokol.data.db.enc`, история начинается заново (это безопасно). |
| `store: cannot decrypt database: bad password` при старте | Пароль не тот, либо файл повреждён. |
| `store: unsupported schema version …` | База создана другой версией приложения. Совместимости со старыми схемами нет: разверните сеть заново из бэкапа. |
| Восстановление: `snapshot … is not supported` или `unknown field` | Файл бэкапа от другой версии или изменён вручную. |
| Восстановление: `snapshot must contain at least one admin machine` | В файле нет admin. Не удаляйте записи машин вручную. |

## Потеряли доступ

- **Забыли токен админки.** Посмотрите `admin ui token` в логе админ-машины (перезапустите клиента, он напечатает его снова) или перезапустите relay с `--token`/`--token-file`. Агенты подключатся,
  как только база разблокируется.
- **Потеряли конфиг админ-машины** (и больше нет admin-токенов). Штатной команды сброса нет.
  Если есть бэкап `dyrokol-config.json`: остановите relay, перенесите прочь `dyrokol.db.enc` и
  `dyrokol.data.db.enc`, запустите, зарегистрируйте новую машину (`client --server …`) и
  восстановите бэкап. Агенты продолжат работать со своими токенами, но им нужно будет подставить
  новый пароль базы. Без бэкапа конфигурацию придётся создавать заново: расшифровать базу без
  пароля невозможно.
- **Потеряли пароль базы**, но admin-машина жива: конфигурацию можно выгрузить бэкапом из
  работающего relay, пока он не перезапущен.

## Что приложить к вопросу

Версия (`Settings → About this relay`), ОС и архитектура, фрагмент логов relay и агента
(**без токенов и паролей**), как устроена цепочка «вход → маршрут → выход».

## Частые вопросы

**Поддерживается ли UDP?** Нет, только TCP.

**Может ли агент подключаться к нескольким relay?** Да: несколько записей в `servers` конфига;
у каждой своя сессия, идентичность и набор портов.

**Нужен ли белый IP на агентах?** Нет: агент сам подключается к relay. Белый IP нужен только relay
(или посетителям нужен доступ к нему).

**Что будет, если relay перезапустится?** Агенты переподключатся сами (пауза 1–15 с); relay
разблокируется, когда подключится агент с паролем базы; порты и маршруты поднимутся из базы.
Активные соединения при этом обрываются.

**Что будет, если пропадёт связь с агентом?** Его входные порты на агенте продолжают слушать,
но соединения отбрасываются (relay недоступен); выходные точки машины показываются как офлайн.

**Можно ли поставить один и тот же порт на разных машинах?** Да: номер уникален в пределах
машины, а не глобально.
