# Админ-интерфейс

Веб-интерфейс встроен в бинарник relay и открывается через админ-машину
(по умолчанию `http://127.0.0.1:9181`). Он работает без интернета: все скрипты и стили
отдаются самим relay.

## Как открыть

У relay **нет админ-порта вообще**: админка отдаётся только админ-машинам через их туннель. Два способа попасть в неё:

1. **Через админ-машину (основной).** На машине с ролью admin агент открывает локальный вход:
   `http://127.0.0.1:9181` (адрес можно сменить `--admin-listen`; если в конфиге клиента несколько relay, у каждого по умолчанию свой порт: 9181, 9182, … в порядке записей). Трафик идёт через туннель.
2. **Необязательный локальный вход на relay** (по умолчанию выключен): запустите relay с
   `--admin 127.0.0.1:9180` (или `admin:` в его конфиге) и пробросьте `ssh -L 9180:127.0.0.1:9180 user@vps`,
   затем откройте `http://127.0.0.1:9180` у себя.

Админка и API появляются **после разблокировки базы**, то есть когда подключилась первая машина
(после перезапуска relay — когда подключится машина с паролем базы). До этого админка недоступна.

## Вход

Экран входа просит **токен админ-API**:

- сгенерированный relay (один раз, хранится внутри его зашифрованной базы): строка `admin ui token: api_…` в логе любой админ-машины;
- или тот, что вы задали флагами (`--token`, `--token-file`);
- или `admin ui token` из лога админ-машины (relay передаёт его туда при подключении).

Это не токен туннеля машины. Токен хранится в `sessionStorage` вкладки и исчезает при её
закрытии; кнопка **Lock** (замок в верхней панели) стирает его сразу. Неверный токен показывает
ошибку, а при истечении или смене токена приложение само возвращается на экран входа.

## Общее устройство

- **Левое меню**: восемь разделов в порядке «вход → выход → маршруты»: Overview, Machines, Ingress ports, Egress ports, Routes, Activity, Logs, Settings. Бейджи: на «Overview» — число проблем, у «Machines» — онлайн/всего,
  у портов — их количество.
- **Имя relay** (Settings → Relay name), если оно задано, показывается слева в верхней панели.
- **Индикатор «Updated … ago»** сверху: данные обновляются каждые 5 секунд, пока вкладка видна
  (в фоновой вкладке опрос приостанавливается). Клик — обновить сейчас. Если relay недоступен,
  индикатор краснеет («Relay unreachable · retry»).
- **Тема**: кнопка солнца/луны переключает светлую и тёмную тему. Выбор запоминается в браузере;
  без него берётся системная.
- **Изменения применяются сразу**: после действия интерфейс обновляется, а успех или ошибка
  показываются всплывающим сообщением. Ошибки форм (например, «порт уже занят») показываются
  прямо в диалоге.
- **Клавиатура**: `Esc` закрывает диалог или меню; фокус возвращается на кнопку, с которой вы пришли.
- **Мобильная версия**: меню выезжает по кнопке-гамбургеру, таблицы прокручиваются по горизонтали.

## Overview

![Обзор](../img/overview.png)

- **Четыре показателя:** машины онлайн, активные соединения, пропускная способность за последнюю
  полную минуту, всего передано.
- **График «Throughput · last hour»:** входящий (посетитель → цель) и исходящий (цель → посетитель)
  трафик по минутам. Наведите курсор: появится вертикальная линия и подсказка со значениями.
  Выпадающий список ограничивает график одним портом. Кнопка **Table** показывает те же данные
  таблицей.
- **Needs attention:** проблемы, ведущие на нужную страницу по клику:

  | Уровень | Когда |
  | --- | --- |
  | `critical` | порт не удалось открыть (bind failed) |
  | `warning` | у порта нет маршрута, трафик отбрасывается |
  | `serious` | машина-цель маршрута офлайн; машина с портами офлайн |

- **Map:** схема маршрутов в том виде, как вы её расставили на странице Routes (только просмотр).

## Machines

![Машины](../img/machines.png)

Таблица машин: имя и начало ключа, роль, статус (онлайн/когда была в сети), адрес последнего
подключения, версия агента, число входных и выходных портов.

| Действие (меню ⋮) | Что делает |
| --- | --- |
| **Add machine** (кнопка сверху) | Создаёт машину, показывает её токен **один раз** и готовую команду запуска агента (`--db-password` в команде только для роли `Admin`: пароль нужен лишь чтобы разблокировать relay после перезапуска). |
| Rename | Меняет метку. |
| Promote to admin / Demote to client | Меняет роль; машина переподключается. Последнего admin понизить нельзя. |
| Regenerate token | Выдаёт новый токен (с префиксом по текущей роли машины: `adm_` у админ-машин, `cl_` у остальных), старый перестаёт работать сразу, машина отключается. Порты и точки машины сохраняются. |
| Delete | Удаляет машину **вместе с её портами, выходными точками и их маршрутами.** |

## Ingress ports

![Входные порты](../img/ingress.png)

Таблица: порт и метка (плюс значок фильтра, если он задан), машина-владелец, цель маршрута
(только показ, со ссылкой на страницу **Routes**), статус, активные соединения, всего соединений,
входящие и исходящие байты. Маршруты здесь не редактируются: для этого есть отдельная страница.

Статусы: `forwarding` (работает), `not routed` (нет маршрута), `target offline` (машина-цель не
в сети), `bind failed` (порт не открылся; причина — под статусом, строка подсвечена).

Диалог **Add ingress port** (и **Edit**):

![Диалог входного порта](../img/ingress-dialog.png)

| Поле | Описание |
| --- | --- |
| Bound on | Машина, на которой порт открывается (только при создании) |
| Port | Номер 1–65535, уникальный в пределах машины. **Номер можно менять и у существующего порта** |
| Label | Метка |
| Source filter | Списки allow/deny для посетителей. Порты в записях не допускаются |

Порт на relay открывается мгновенно; если он занят на хосте relay, создание отклоняется с ошибкой.
При смене номера у порта на relay старый сокет закрывается и открывается новый; если новый номер
занять не удалось, изменение откатывается и показывается ошибка (порт продолжает работать на
прежнем номере). У порта на агенте новый номер применяется при ближайшей доставке конфигурации.
Порт на агенте открывается при ближайшей доставке конфигурации, а при неудаче статус
`bind failed` появляется в таблице. Меню ⋮: **Edit**, **Routes…** (переход на страницу маршрутов), **Delete** (закрывает порт
и активные соединения). Маршруты на этой странице не редактируются.

## Routes

![Маршруты](../img/routes.png)

Страница состоит из **таблицы маршрутов** (вверху) и **схемы** (под ней).

### Таблица

**Одна строка — один маршрут: «входной порт → выходной порт».** Строки правятся прямо на месте:

- круглая **кнопка вкл/выкл** в начале строки переключает маршрут: **зелёная** — включён, **красная** —
  выключен. Выключенный маршрут остаётся в таблице (ничего не теряется), но трафик не пропускает:
  входной порт ведёт себя так, будто маршрута нет, активные соединения закрываются, порты на
  агентах освобождаются. Статус — `route off`, линия на схеме становится серой пунктирной;
- затем выбирается входной порт (в списке сам порт строки и те входные порты, у которых ещё нет
  маршрута), справа выходной порт; смена любого из двух сохраняется сразу;
- справа состояние (`forwarding`, `target offline`, `bind failed`, `route off`) и кнопка-корзина, удаляющая
  маршрут (активные соединения этого порта закрываются);
- последняя строка (выделена) — **новый маршрут**: выберите входной порт без маршрута, выходной
  порт и нажмите **Add route**.

Несколько входных портов в одну выходную точку — это просто несколько строк с одним и тем же
выходным портом; строки отсортированы по выходному порту, так что такая группа идёт подряд.
У каждого входного порта маршрут один, поэтому один и тот же входной порт в двух строках быть не
может (он исчезает из списков, как только получил маршрут).

### Схема

Справочная картинка того, что настроено в таблице. Каждый порт — узел (виден номер, метка,
машина и состояние), маршрут — линия. Наведите курсор на порт, и подсветится всё, что с ним
связано. Состояние всегда подписано словом, а не только цветом:

| Элемент | Значение |
| --- | --- |
| синяя линия | `forwarding`: трафик идёт |
| оранжевая пунктирная | `target offline`: машина-цель не в сети |
| красная линия | `bind failed`: порт не удалось открыть |
| узел с пунктирной рамкой | `not routed` (входной) или `unused` (выходной): к нему ничего не подключено |

**Движение трафика.** По линии маршрута бегут точки: зелёные — от входа к выходу, оранжевые — обратно. Чем больше трафика (скользящее среднее за последние опросы), тем больше точек и быстрее они движутся; когда трафик прекращается, точки продолжают двигаться и плавно гаснут (примерно за 5–10 секунд). При системной настройке «уменьшить анимацию» точки не показываются.

**Схему можно приближать, двигать и раскрывать на весь экран** (на странице Routes и на Overview).
Управление справа над схемой: **− / 100% / +** (клик по проценту возвращает 100%), **Fit** (вписать
всё содержимое в окно) и **Full screen**:

- **Двигать схему:** потяните за пустой фон (пальцем так же; двумя пальцами щипок масштабирует).
- **Масштаб:** кнопки − и +, либо **Ctrl (⌘) + колесо** (на тачпаде щипок). Обычное колесо
  прокручивает страницу, а в полноэкранном режиме масштабирует схему. Диапазон 20–300 %.
- **Full screen** раскрывает схему на всё окно и включает полноэкранный режим браузера. Выйти можно
  кнопкой там же или клавишей `Esc` (диалоги, например Auto-arrange, открываются поверх схемы,
  и первое нажатие `Esc` закрывает диалог). Редактирование работает и в полноэкранном режиме.
- Положение и масштаб обзора запоминаются только в браузере и не сохраняются на сервере (в отличие
  от расположения портов, рамок и подписей).

**Схему можно расставить как удобно:**

- **Перетаскивайте порты** мышью или пальцем: позиция запоминается. Шаг сетки 10 пикселей, при любом масштабе порт
  уходит ровно за курсором.
- **Text** добавляет текстовую подпись, **Frame** — рамку (например, «Домашняя сеть» вокруг
  портов дома). Выделите элемент, чтобы изменить текст, цвет (6 цветов) и размер подписи (S/M/L),
  потянуть за угол рамки (она меняет размер) или удалить кнопкой **Delete** либо клавишей `Delete`.
  Двигаются они так же, перетаскиванием.
- **Слои:** снизу вверх идут рамки, подписи, линии и порты. Подписи и рамки никогда не закрывают
  ни порты, ни линии.
- **Auto-arrange** возвращает порты на места по умолчанию (левая колонка входных, правая
  выходных); рамки и подписи остаются.
- Порты, которым вы ещё не назначили место (например, новые), встают в свою колонку под уже
  расставленными.

Раскладка **общая для всех администраторов** и сохраняется на relay автоматически (через полсекунды
после последнего изменения); она входит в бэкап конфигурации. Те же расставленные порты показаны
на странице **Overview** (там схема только для просмотра). На узком экране схему можно двигать и масштабировать так же.

## Egress ports

Таблица выходных точек: цель, машина-исполнитель, тип, статус машины,
число ведущих сюда маршрутов.

![Диалог выходной точки](../img/egress-dialog.png)

Поля: *Exits on* (машина), *Type* (Direct/SOCKS5), *Target host* (по умолчанию `127.0.0.1`,
**с точки зрения исполняющей машины**) и *Port*; для SOCKS5 цели нет: только необязательные логин и пароль встроенного SOCKS5-сервера;
метка и *Destination filter* (там порты допустимы: `*:25`, `host:443`).

При редактировании меняются **цель (хост и порт, только direct), логин SOCKS5, метка и фильтр**. Машина и тип
фиксированы: чтобы переместить точку на другую машину или сменить тип, создайте новую, перенесите
на неё маршруты (достаточно сменить выходной порт в строках таблицы Routes) и удалите старую.
Нельзя сделать две одинаковые точки (машина, тип, цель и прокси совпадают). Новая цель
действует для новых соединений; уже открытые продолжают идти на прежнюю. При удалении точки
ведущие к ней порты становятся нерутированными, а их активные соединения закрываются.

## Activity

Две вкладки с общим поиском (по адресу, порту, имени):

- **Live connections** — соединения, открытые прямо сейчас: адрес посетителя, порт (`машина:порт`),
  какая машина его обслуживает, сколько времени соединение открыто. Обновляется каждые 3 секунды
  (показывается до 500 соединений от каждого агента).
- **Seen addresses** — адреса посетителей за последние 24 часа: число соединений, байты,
  первое и последнее появление.

## Logs

События relay за 7 дней: инициализация и разблокировка базы, подключения и отключения машин,
ошибки bind, отклонённые рукопожатия, отвергнутые конфигурации, восстановление из бэкапа.
Фильтр по уровню (`info`, `warn`, `error`) и текстовый поиск; показываются последние 1000 записей.

## Settings

![Настройки](../img/settings.png)

- **Relay name** — отображаемое имя этого relay. Показывается в верхней панели админки (и в заголовке
  вкладки браузера), удобно, когда вы управляете несколькими relay.
- **Public address** — домен или IP, по которому агенты подключаются, с необязательным портом (по
  умолчанию `7443`), например `relay.example.com`. Хранится в базе и только подставляется в команду
  запуска агента в диалоге **Add machine**; сам relay его не использует.
- **Start on boot** — флаг, который хранится в базе; сам по себе ничего не запускает. Автозапуск
  настраивается службой ОС: `dyrokol service install` на Windows, systemd на Linux (см.
  [Развёртывание](deployment.md)).
- **Backup and restore.**
  *Download backup* скачивает `dyrokol-config.json`, *Without proxy passwords* — то же без паролей
  SOCKS5 (файл безопасно показывать другим). *Restore…* заменяет **всю** конфигурацию из файла,
  отключает всех агентов (они переподключатся) и очищает статистику.
  В бэкап входят и расположение портов на схеме с рамками и подписями. Не попадают токены машин, пароль базы и история трафика.
- **About this relay** — версия, версия протокола, адреса, файл базы, версия конфигурации,
  отпечаток TLS-сертификата (его сверяют при первом подключении агентов).
- **Danger zone → Shut down** — останавливает процесс relay. Запустить его снова нужно на самом
  хосте; админка после этого, естественно, перестанет отвечать.
